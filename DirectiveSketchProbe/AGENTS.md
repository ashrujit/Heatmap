# DirectiveSketchProbe - Two-Box Directive Sketch Probe

## Intent

This is a disposable proof project for using a custom two-box chart sketch as
the spatial input device for future EAR directive drafting.

The probe must not write EAR's active `directive.json`, must not dispatch, and
must not make execution decisions. It only captures an explicitly armed chart
gesture and writes a separate JSON snapshot so we can verify whether Dispatcher
can later import the sketch.

## Design Invariants

- Stay on the published BusinessLayer chart surface: chart mouse events,
  coordinate conversion, and `OnPaintChart`.
- Idle mode must only hit-test the fixed status rectangle. Ordinary chart
  clicks and drags outside that rectangle pass through to Quantower.
- Armed mode captures one left-drag. The first-click price is the outer
  Order/Context boundary. The drag distance defines the Order/Context range,
  and a small TP cap is generated just beyond the drag endpoint. Dragging up
  creates TP above Order/Context; dragging down creates TP below Order/Context.
- The two boxes must be generated by geometry that prevents overlap. A short
  accidental click must not produce a draft; the Order/Context side has to move
  by at least the configured minimum order height.
- Draft-ready sketches expose three draggable price handles: the Order/Context
  outer boundary, the shared boundary, and the TP target boundary.
- Visual side should be readable without checking JSON or Dispatcher: green
  Order/Context means long, red Order/Context means short, and TP remains
  neutral blue. Labels stay outside their boxes but are centered against the
  rectangle so dragged boundaries remain the primary visual anchor.
- Output is a draft artifact for Dispatcher research only. Runtime safety stays
  with Dispatcher validation and EAR's immutable directive contract.
